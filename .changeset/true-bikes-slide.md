`node tests/new_culture.mjs <id> --iso <CODE>` starts a culture from the canon
instead of from memory of it.

Ten cultures arrived carrying the same seven defects - `Event` where the canon
says `Action`, a play with `Taxonomy` and `Owner` and no `Triggers`, personas
with no `type`. Ten identical sets is not ten mistakes; it is one remembered
shape, reused. Nine of the ten were branched from a base whose rules already
tabled the right chapters, so the rules were not the missing piece: a list you
read is not a file you were handed.

`@chbrain/khai-arch` has shipped `templates` for all nine types the whole time -
complete files, right chapters, right order, right frontmatter. Nothing in this
house ever called it. Three files import `types` to VALIDATE and none imported
`templates` to WRITE, and the rules pointed at `types` for chapter names, which
is the validation data and not the file.

So this stamps them, and adds the packaging the canon does not know about: the
manifest, the umbrella reference, an umbrella-only changeset, the instructions
file. It decides no content, and every chapter it writes is marked `TODO` so
`khai-staging` names it until it is written - the template's guidance prose is
plain enough that staging passed it silently, which would have let an unedited
scaffold reach a pull request looking green.

The chapter table added to these rules two days ago is deleted here. It was a
third copy of `khai-arch`'s `types`, and the second copy is what this house keeps
learning not to keep.
